# 设计：v1.0.15 —— 体积瘦身 + 全量备份 + 测试与 CI

日期：2026-10-09
状态：已获用户批准（对话中逐条确认后口头批准）

## 背景与目标

对 magic-castle 做一轮有数据支撑的优化：降低首装体积、堵住备份数据缺口、补上最低限度的
质量保障（测试 + CI）。范围在前期评估的 11 条候选中由用户圈定为 3 组（原计划的 1、2、4、6）。

## 已确认的决策

### ① 冒险地图背景图转 WebP

- 现状：`assets/scenes/adventure-map/magic-castle-adventure-map.jpeg` **820K**(1312×816)、
  `...-mobile.jpeg` **635K**(720×1456)，Service Worker `APP_SHELL` 两张都预缓存，运行时按断点只用一张。
- 方案：用 Pillow 转 WebP（quality=80），**保持原尺寸不变**（移动端 720 宽在 2x 屏已够，
  改尺寸引入裁切风险，收益叠加有限）。
- 同步修改：`styles/screens/adventure-map.css` 的 `background-image` 路径、`service-worker.js` 的 `APP_SHELL`。
- 原 jpeg **从仓库删除**（回滚靠 git）。
- 不做 JPEG 回退：目标环境（Android WebView、iOS Safari 14+、Chrome/Edge/Firefox）全部支持 WebP。
- 预期：1.46MB → 约 200–400K（以实测为准）。

### ② 背景音乐 WAV → M4A(AAC)

- 现状：`assets/audio/magic-house/background-loop.wav` **261K**，`app.js` 中 `new Audio(...)` 播放，
  并在 SW `APP_SHELL` 中预缓存。
- 方案：`ffmpeg -i background-loop.wav -c:a aac -b:a 96k background-loop.m4a`。
  **选 M4A/AAC 而非 OGG**：iOS Safari 对 OGG Vorbis 支持不稳定，AAC 三端通吃。
- 同步修改：`app.js` 的 `new Audio()` 路径、SW `APP_SHELL`；删除原 `.wav`。
- 预期：261K → 约 30–50K（以实测为准）。

### ③ 备份从"学习记录"扩为"全量"

- 现状：`exportProgress()` 只导出 `{version:1, exportedAt, activeProfileId, profiles}`。
- **不在备份中、清缓存/换机会丢的数据**（本项的核心缺口）：
  - `luna-admin-content-v4`（家长编辑的词组/汉字组/古诗分组，人工成本最高）
  - `luna-global-speech-rate`（朗读语速）
  - `luna-parent-mode-enabled`（家长模式开关）
- 方案：
  - 导出 payload 升为 `version: 2`，新增 `adminContent`、`speechRate`、`parentMode` 字段。
  - 导入：`version===2` 恢复全部四项；`version===1` 沿用现有逻辑（旧备份文件保持可用）；
    其它一律走现有"无法导入"错误提示。导入前保留 `window.confirm`。
  - `adminContent` 做结构校验（对象、且至少含一个已知分组字段），不合法则忽略该项而非整体失败。
  - 解析逻辑抽为纯函数 `parseBackupPayload(data)`（返回结果对象，不触碰 DOM/存储），
    供 ④ 的测试直接调用。
  - 按钮文案："导出学习记录/导入学习记录" → "导出备份/导入备份"，描述文案同步。
- 不引入新按钮、不做云同步、不做自动定时备份（YAGNI）。

### ④ 测试 + CI（零新依赖）

- `package.json` 增加 `"test": "node --test tests/"`，用 Node 内置 test runner。
- 用例覆盖（均为可独立 import 的 `features/` 纯模块 + 新抽的解析函数）：
  - `features/arcade-games.js`：关卡参数随关数单调递增；`createMemoryDeck` 对数与目标一致、
    无重复图案；**每关必可通关**的不变量（防止"翻翻乐卡死"回归）。
  - `features/storage.js`：JSON 损坏时回退到 fallback、写入异常时触发 `onError`。
  - `features/theme-catalog.js`、`features/content-catalog.js`：条目必填字段完整性。
  - 备份：`parseBackupPayload` 对 v1/v2/非法输入的行为。
- 模块机制：测试以 `.mjs` 编写；若 `features/*.js` 因 package.json 缺 `"type": "module"`
  而被 Node 当作 CJS 解析，则**给 package.json 加 `"type": "module"`**，并回归验证
  `node --check app.js`、`npm run build:web`、`npm run apk:debug` 全部通过；
  若出现破坏则改用其它方案（如测试文件内联复制待测逻辑——优先避免）。
- CI：`.github/workflows/ci.yml`，`push`/`pull_request` → Node 20 →
  `npm ci` → `node --check app.js` → `npm test` → `npm run build:web`。
- **CI 不构建 APK**：Gradle 与签名留在本地，避免复杂化发版流程。

## 明确不做（本轮范围外）

- vendor 小游戏资源移出首次预缓存
- `style.css` 按屏拆分
- 字体进一步瘦身（已接近最优：子集=GB2312 一级字全集）
- 图片懒加载/尺寸占位（体验类，留待下轮）
- 朗读自检入口（产品类，留待下轮）

## 实施步骤

1. 图片：Pillow 转 WebP → 更新 CSS + SW → 删 jpeg → 记录实测体积。
2. 音频：ffmpeg 转 M4A → 更新 `app.js` + SW → 删 wav → 记录实测体积。
3. 备份：抽 `parseBackupPayload`、升级导出/导入逻辑、改按钮与描述文案。
4. 测试：建 `tests/`、必要时调整 package.json `"type"`、实现上述用例，`npm test` 全绿。
5. CI：新增 workflow，推送到 GitHub 后确认 Actions 通过。
6. 版本：`versionCode 16` / `versionName 1.0.15`、SW 缓存键、`?v=`、`features/build-info.js`。
7. 验证与发布：`node --check`、`npm test`、`npm run apk:debug`，打 tag `v1.0.15`，发 GitHub Release（含 APK）。

## 验收标准

- 两张地图背景转 WebP 后总体积 ≤ 400K，页面视觉无明显劣化。
- 背景音乐 M4A 体积 ≤ 60K，魔法屋音乐在 Android 与网页端均可播放、后台暂停行为不变。
- 导出的 v2 备份包含自定义内容与设置；v1 旧备份仍可导入；非法 JSON 仍被拒绝。
- `npm test` 全绿，CI workflow 在 push 后通过。
- APK 构建通过并发布 v1.0.15。

## 风险

- WebP/M4A 属格式替换：若目标 WebView 对某格式异常（可能性低），回滚成本为 git revert 一次提交。
- `package.json` 加 `"type": "module"` 可能影响既有 Node 脚本 —— 已列为必测项。
- CI 首次运行可能暴露 `npm ci` 与 lock 文件不一致，需现场修。
